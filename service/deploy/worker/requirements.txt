# What the worker's venv contains, pinned to the versions this was measured with.
#
# `install.sh` feeds this to `uv pip install`. Pinning is not tidiness: the alignment is a
# DTW over chroma features, so a librosa or numpy change is a change to the numbers a
# finished piece reports. The measured ones (bar 1-18 of the Chopin waltz = 30.53 s, and the
# 8.6 s / 10.0 s job times) belong to this set.
#
# **Python 3.12 is required, and that is why uv is used.** The system python on Ubuntu 22.04
# is 3.10, and on 3.10 pip stops at librosa 0.11.0 -- a different version, and there is no
# reason to risk a map that differs from the one this repository's own tests and
# documentation quote. `uv` fetches a standalone 3.12 without root and without touching the
# system interpreter.
#
# The list is longer than the pipeline needs, and the reason is upstream: `memorization/
# analyze.py` does `import note_seq`, whose `__init__` imports `note_seq.notebook_utils`,
# which imports bokeh and IPython, and `midi_io`/`sequences_lib` need pretty_midi and
# pandas. So `bokeh`, `ipython`, `pandas` and their dependencies are here because of a
# package-level import, not because the alignment uses them.
#
# Regenerate after a deliberate upgrade by reinstalling into a fresh venv and running
# `pip freeze`, then documenting what changed in the numbers -- not by copying a freeze from
# a machine whose map was never compared.
